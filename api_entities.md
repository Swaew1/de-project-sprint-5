## 1. Список полей, необходимых для витрины `cdm.dm_courier_settlements`

Витрина рассчитывается с группировкой по курьеру, году и месяцу

`id` — уникальный идентификатор записи (Primary Key, генерация в CDM);
`courier_id` — ID курьера из системы доставки;
`courier_name` — Ф.И.О. курьера;
`settlement_year` — отчетный год (извлечён из даты заказа);
`settlement_month` — отчетный месяц (1–12, извлечён из даты заказа);
`orders_count` — общее количество доставленных заказов курьером за месяц;
`orders_total_sum` — суммарная стоимость доставленных заказов курьером за месяц;
`rate_avg` — средний рейтинг курьера за расчётный месяц по всем оценкам;
`order_processing_fee` — комиссия компании за обработку (25% от `orders_total_sum`);
`courier_order_sum` — сумма выплаты курьеру за заказы (с учётом порога ставки от рейтинга и минимальной платы за заказ);
`courier_tips_sum` — суммарный размер чаевых, оставленных курьеру;
`courier_reward_sum` — итоговая сумма к перечислению курьеру (`courier_order_sum + courier_tips_sum * 0.95`).

## 2. Список таблиц в слое DDS для формирования витрины

### Таблицы:

1. `dds.dm_orders` (Существующая)
    *Назначение:* Хранит информацию о заказах и их статусах.
    *Поля для витрины:* `id`, `order_key` (для связи с `order_id` доставки), `timestamp_id`.

2. `dds.dm_timestamps` (Существующая)
    *Назначение:* Справочник дат и времени.
    *Поля для витрины:* `id`, `year`, `month`, `date` (для фильтрации и группировки по дате заказа).

3. `dds.fct_product_sales` (Существующая)
    *Назначение:* Факты продаж по товарам в заказах.
    *Поля для витрины:* `order_id`, `total_sum` (агрегируется для получения общей стоимости заказа `orders_total_sum`).

4. `dds.dm_couriers` (Новая)
    *Назначение:* Справочник курьеров.
    *Поля для витрины:* `id`, `courier_id`, `courier_name`.

5. `dds.fct_deliveries` (Новая)
    *Назначение:* Таблица фактов доставок заказов курьерами.
    *Поля для витрины:* `id`, `order_id` (FK на `dm_orders`), `courier_id` (FK на `dm_couriers`), `delivery_ts`, `rate`, `tip_sum`.

## 3. Сущности и поля, необходимые для выгрузки из API

Для заполнения новых таблиц DDS требуется использовать два метода API (метод `/restaurants` не используется, так как рестораны уже есть в DWH):

### 1. Метод `/couriers`
* `_id` — идентификатор курьера (мапится в `dds.dm_couriers.courier_id`);
* `name` — имя курьера (мапится в `dds.dm_couriers.courier_name`).

### 2. Метод `/deliveries`
* `order_id` — ID заказа (мапится в `dds.fct_deliveries.order_id` через связь с `dds.dm_orders.order_key`);
* `delivery_id` — ID самой доставки;
* `courier_id` — ID курьера (мапится в `dds.fct_deliveries.courier_id` через связь с `dds.dm_couriers`);
* `order_ts` — timestamp создания заказа;
* `delivery_ts` — timestamp совершения доставки;
* `rate` — оценка работы курьера (1–5);
* `tip_sum` — размер чаевых.
